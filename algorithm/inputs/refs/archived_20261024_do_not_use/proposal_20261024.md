# 产品名称
智能风控实战项目 - 银行流水算法模块（MVP版）

# 关键交付物
1. **OCR解析接口（Mock版）**：输入PDF/图片，输出符合数据模型规范的结构化流水JSON。
2. **风控指标计算服务**：基于Pandas实现7项核心统计指标的计算逻辑。
3. **风险标签与评分引擎**：基于正则表达式的附言摘要挖掘、综合评分计算及四维雷达图数据生成。
4. **报告数据聚合服务**：按月度聚合收支趋势数据，并输出带风险标签的流水明细列表。
5. **算法服务代码与文档**：基于 FastAPI 的接口代码、Pydantic 数据模型定义及相应的 API 文档。

# 前端功能需求
*(注：算法侧不直接开发前端页面，仅向后端及前端提供渲染所需的数据接口契约)*
1. **风险雷达图数据**：需提供包含“稳定性、负债、合规、异常”四个维度的 0-100 分值数组，供前端 ECharts 渲染。
2. **收支趋势图数据**：需提供按月聚合的 `{ month, income, expense }` 数组，供前端渲染折线图/柱状图。
3. **风险标签与高亮**：需返回综合评分（0-100）、风险等级（高/中/低）、命中风险标签的汇总列表，以及逐笔流水中附言命中的标签 `[LOAN]`、`[GAMBLING]`，供前端高亮展示。
4. **收支统计卡片**：需返回总收入、总支出等核心卡片数据。

# 后端功能需求
本模块作为后端服务的一部分，由 FastAPI 提供 RESTful 接口。所有接口必须遵循统一响应结构：`{"code": 0, "message": "success", "data": {...}}`。

**1. 文件解析与任务处理接口（Mock支撑）**
*   **接口定义**：接收前端上传的流水文件及分析参数（如起止时间），生成 `taskId` 并返回解析进度。
*   **算法逻辑**：当前阶段使用 Mock 数据模拟 OCR 解析耗时与结果，输出标准的结构化交易字典列表。

**2. 风控指标计算（核心数据处理层）**
算法侧需提供 Python 函数/类，对解析后的流水进行清洗与计算，严格实现以下 7 个指标（口径要求）：
*   `income_total`：所有 credit (收入) 金额之和。
*   `expense_total`：所有 debit (支出) 金额之和。
*   `net_flow`：`income_total - expense_total`（净流入）。
*   `closing_balance`：最后一笔交易完成后的余额。
*   `avg_balance`：所有交易后余额的算术平均值。
*   `transaction_count`：交易总笔数（去重、剔除无效记录后）。
*   `cash_ratio`：现金类交易笔数 ÷ 总交易笔数。

**3. 风险规则引擎（打标与评分）**
*   **敏感词打标**：基于正则表达式扫描 `summary`（摘要）字段。包含“小贷|网贷”则赋标签 `[LOAN]`；包含“博彩|赌”则赋标签 `[GAMBLING]`。若未命中则为空。
*   **综合评分模型（规则版）**：
    *   基础分 100 分。
    *   若命中 `[LOAN]` 扣 30 分；命中 `[GAMBLING]` 扣 50 分。
    *   结合 `net_flow`、`cash_ratio` 等指标给予微小权重调整（如现金流为负扣 10 分）。
    *   输出 `risk_score`（0-100）与 `risk_level`（>80低风险，60-80中风险，<60高风险）。
*   **四维雷达图评分**：基于上述指标进行归一化处理，输出四个维度的得分（稳定性得分、负债得分、合规得分、异常得分）。

**4. 报告数据聚合与输出接口**
*   **接口定义**：`GET /api/tasks/{taskId}/report`。
*   **算法逻辑**：将上述 7 个指标、评分、雷达图数据、月度趋势（对交易日期按月分组求收支和），以及带有 `riskTags` 标记的逐笔流水列表，组装成前端所需的完整 JSON 返回。

# 非功能需求
1. **性能要求**：解析+分析服务响应时间 <= 5s @99%（当前阶段为 Mock 与轻量级 Pandas 计算，耗时主要在 IO，必须保证无性能瓶颈）。
2. **数据格式**：日期时间必须强制使用中国本地时间（UTC+8），格式为 `YYYY-MM-DD` 及 `YYYY-MM`。
3. **数据规范**：所有 API 输入与输出必须使用 Pydantic 定义数据模型（Schema），严禁使用裸字典直接返回。
4. **精度要求**：金额计算必须使用 `Decimal` 类型或确保保留两位小数，避免浮点数精度丢失问题。

# 开发规范要求
1. **技术栈**：Python 3.10+，FastAPI，Pydantic，Pandas。
2. **工程目录规范**：
    *   `schemas/`：存放 API 接口数据模型（Pydantic）。
    *   `models/`：存放数据库 ORM 模型（若当前阶段需入库）。
    *   `services/`：存放核心业务逻辑（如 `risk_service.py` 用于计算指标，`parser_service.py` 用于解析 Mock）。
    *   `routers/`：存放 FastAPI 路由代码。
    *   `config.py`：存放系统运行依赖环境变量（数据库连接等），禁止硬编码。
3. **开发范式**：严格采用 Vibe Coding + SDD 规范，代码需结构清晰、注释完整，关键逻辑（如正则匹配、指标计算）必须有对应的注释说明。每轮对话后维护 `memory.md`。
