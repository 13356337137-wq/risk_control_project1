# 2026-10-29 · 07 · 六类剔除与 40 项指标

## 意图

按组长三项交付之「每个风控指标的计算方式」，先做 AL-10 六类剔除，再做 AL-11 40 项指标；两者都要能在真实脱敏流水上复算，并对缺字段保持 null，不填 0、不估算。

## 改动

- 新增 `algo/exclusions.py`
  - 六类按固定顺序匹配，一笔只归一类：同名互转 → 退款冲正 → 贷款放款 → 理财赎回申购 → 信用卡还款取现 → 他人代付。
  - 同名互转按对手方与本人姓名（去空格/掩码符）或摘要「本人/同名/内部划转/归集」识别；未传本人姓名时写入 notes。
  - 贷款放款同时认摘要词与放贷机构对手方；「代发工资」不命中「代付」。
  - 他人代付要求入账、摘要含代付、对手方为机构，标 `needs_review=True`，先剔除再交人工认定。
  - 输出逐笔 `ExcludedTxn`（页、行、日期、摘要、对手方、金额、类别、原因）、分类合计、剔除前后入账/出账合计。
- 新增 `algo/metrics.py`
  - 固定输出 A01–A08、B01–B08、C01–C08、D01–D08、E01–E08 共 40 项；`METRIC_SET_VERSION = 1`，单项 `caliber_version = 1`。
  - 缺输入返回 `value=None` + 原因；`MetricSet.notes` 放全局说明，不污染单项。
  - 百分比统一 0–1；标准差用总体标准差；月均收入 = 剔除后入账 ÷ 覆盖自然月数，空月计 0。
  - 日终余额按交易余额还原、无交易日结转；期初余额未知时首笔前日期不计。
  - 负债类 B01/B03–B06 用原始明细，不因收入剔除而少算。
  - `MetricSet` 带 period、coverage_months、notes 与剔除结果。
- `algo/__init__.py` 导出 `analyze_exclusions / compute_metrics / ExclusionResult / MetricSet / MetricValue / METRIC_SET_VERSION`。
- 新增 `tests/test_exclusions.py`（11 项）与 `tests/test_metrics.py`（12 项）。
- 更新 `tasks.md`（AL-10/11 勾选）、`algo/README.md`（剔除与指标口径）、`chat.md`（裁决与待处理）。

## 遗留

- 真实样本剔除额很小，说明该账户本身以消费为主；六类规则对工资户的剔除效果还没有大额借款/自转样本验证。
- E01/E02 有 58 笔无对手方，只按有名称的 44 笔计算并在 note 注明；对手方字段完整度是这批指标的主要制约。
- 微信零钱提现 8 笔未命中六类，按普通入账计入收入，可能高估；需确认是否加「内部划转」类。
- B06 只认摘要含「信用卡」，4 笔「还款」对手方为支付宝，暂未计入 B06。
- D07 两笔工资入账日相同，波动为 0，样本不足以验证工资日波动。
- 百分比刻度 0–1 尚未写进 contract，需 PM/PD 确认后端入库口径。

## 裁决

- 剔除顺序固定，先命中先归类；他人代付先剔除、标人工认定，避免收入高估。
- 指标缺输入一律 null + 原因；不因缺字段返回 0，避免把「不知道」算成「没有」。
- 负债类指标用原始明细，收入类用剔除后明细；同一笔还款在 B 组仍计入负债，不影响 A 组收入。
- 指标集与单项口径版本均从 1 起，只增不改；后续口径变化改单项版本，不改历史值。
