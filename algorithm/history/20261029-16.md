# 2026-10-29 #16 阈值整版 JSON 导出

## 意图

上一轮核对组长要求（`Agent.md:9-17`）后确认：阈值在数据库怎么存归数据组、配置接口归后端，算法组只负责清单与版本；但报告只落 `threshold_version`（int）与触发项，旧报告回查不到整版配置。算法组能补的最小交付是提供一个整版快照导出，供数据组建表种子与后端按版本归档，不碰库、不改报告结构。

## 改动

- `algo/thresholds.py`：新增 `export_thresholds(config=None) -> str`，`ThresholdConfig.model_dump_json(indent=2)`；Decimal 在 pydantic v2 的 JSON 模式下序列化为字符串，精度不丢。
- `algo/__init__.py`：导出 `export_thresholds` 并加入 `__all__`。
- `tests/test_thresholds.py`（新建，3 项）：
  - 导出键集必须等于 `ThresholdConfig.model_fields`，`version` 等于 `THRESHOLD_VERSION`，`counterparty_hhi` 为 `None`（未校准不判定）；
  - `model_validate_json` 回读等于 `DEFAULT_THRESHOLDS`（往返一致）；
  - 自定义配置（version=7、dti_high=0.6）按传入值导出。
- `algo/README.md`：模块行补「整版导出」；阈值小节加 `export_thresholds()` 说明（报告不带全量阈值）。
- `algorithm/chat.md`：阈值存储口径待办补「算法侧已提供 `export_thresholds()`（2026-10-29）」。

## 遗留

- 阈值配置表结构仍缺：contract 表清单（`contract.md:115-127`）无 threshold 表，只有 `rule.threshold` json；report 表字段（`:123`）未列 `threshold_version`/`conclusions`，与报告 JSON（`:90-101`）不一致。归数据组与 PM/PD。
- 版本归档流程（PUT 写新版本、旧版本保留）归后端，未实现。
- 导出函数未加 `THRESHOLD_VERSION` 一致性断言：若有人手改 `ThresholdConfig.version` 却不动常量，导出会跟着改；当前由模型字段默认值与常量共用保证，暂不额外校验。

## 裁决

- 阈值只以「版本号 + 触发项」进报告，不加快照字段（contract 12 字段不扩）；整版配置靠版本表解释，导出只做数据交接格式。
- 导出保留 Decimal 字符串形态，不转 float，避免 0.1/0.3 这类默认值在 JSON 中失真。
