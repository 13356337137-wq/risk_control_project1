# 2026-10-29 · 03 · OCR 引擎适配层（RapidOCR）

## 背景

行内确认没有 OCR 服务，影像件只能本机部署开源引擎。选定 RapidOCR：模型随包、离线可用，坐标与置信度满足解析需要；先做适配层，不改电子件快路径。

## 做了什么

- 安装 `rapidocr_onnxruntime==1.4.4`，模型随包（det 4.6M / rec 11M / cls 572K），运行时不联网。
- 新增 `algorithm/ocr/engine.py`：
  - `OcrWord / OcrPage / OcrResult`：每词 `text + bbox(x0,y0,x1,y1) + confidence`，每页带宽高与页码。
  - `OcrEngine` Protocol；`RapidOCREngine` 懒加载后端，图片走 `cv2.imdecode`，PDF 用 PyMuPDF 按 200 DPI 渲染后逐页识别。
  - 空文件、解码失败、加密 PDF、引擎缺失统一抛 `OcrUnavailable`。
- `ocr/__init__.py` 导出引擎类型；`parse.py` 只改错误文案，仍只处理电子件文字层。
- 新增单测 `tests/test_engine.py`（假后端，5 例）与集成测试 `tests/integration/test_rapidocr_engine.py`（合成中文流水图，真实模型）。
- `requirements.txt` 增加 RapidOCR，并锁 `onnxruntime==1.20.1`。

合成图识别到 `2026-08-01`、`+5,000.00`、`5,024.58`、`-29.00`、`4,995.58`，置信度均在 0~1。

## 踩坑

- 机器上原有的 `onnxruntime 1.31.1` 导入即 access violation，降级到 1.20.1 后正常；已在 requirements 注明。
- `rapidocr_onnxruntime` 对 ndarray 输入按 BGR 处理，PDF 渲染出的 RGB 需先转 BGR，否则颜色通道错位。
