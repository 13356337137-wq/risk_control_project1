# 2026-10-29 · 12 · AL-16 准确率评测与抽错归因

## 意图

补上 AL-16：用 AL-15 的清单驱动全链路回归，输出可复现的准确率指标，并把每处偏差归到「识别 / 版式 / 规则 / 参数 / 误报 / 五态」六类之一，满足 design V1、V4–V7；V2/V3 等真实件与模糊样本到位后再测。

## 改动

- 新增 `algo/eval.py`
  - 单份流程：`parse()` → `analyze_content()` → `analyze_file()` → `analyze_ledger()` → `analyze_external()` → `conclude()`，与线上链路同序。
  - 模型：`EvalCaseResult`（期望/实际五态、笔数、失败码、缺码/多码、归因、证据）、`EvalSummary`（六项指标 + `by_cause`）、`EvalReport`（`eval_version=1`、样本集版本、逐份结果）。
  - 指标口径：样本通过率、五态准确率、笔数准确率、必需失败码召回、伪造检出、干净件误判。
  - 比对规则：伪造件必需失败码按子集判定，多出的码记 `extra_codes` 不判错；干净件出现任何失败码即记 `false_positive`。
  - 归因映射：缺 F4/F10/E* 记 `parameter_missing`，其余 F 记 `rule_gap`；A1/A3/A4/A5/A6 记 `parameter_missing`，A2/A7 记 `rule_gap`；C 组在低置信占比 > 0 或内容层已归因识别时记 `recognition`，否则 `rule_gap`；笔数错时低置信行存在记 `recognition`，否则 `parsing`；五态不符记 `verdict_logic`。
  - CLI：`--samples`（默认 `algorithm/inputs/samples/synthetic`）、`--build`、`--json`、`--strict`；清单缺失返回 2 并提示先跑 `python -m algorithm.algo.samples`。
  - 报告确定性：不含时间戳；失败样本打印页码、行号与坐标（最多两条证据）。
- 新增 `tests/test_eval.py`（9 项）：全量通过、确定性、缺 A1 归因参数缺失、干净件失败码归因误报、笔数错归因解析、五态错归因裁决、CLI JSON、缺清单返回 2、报告含归因。
- `algo/__init__.py` 不导出 eval，避免 `python -m` 触发 RuntimeWarning。
- 文档：`algo/README.md` 模块表加 `eval.py`，新增「样本评测当前口径」；`tasks.md` 勾选 AL-16；`chat.md` 记裁决与残留；`inputs/README.md` 无需再改。

## 遗留

- 6/6 全绿只说明链路自洽：样本由本仓库生成，伪造手法与检测项同源，不能当作真实召回率。V2「每 10 份真件误判 ≤1」、V3「低置信识别归因」仍无数据。
- design V1 的删行、拼页、换利率、整份重排四类伪造未进样本集，评测覆盖不到对应分支。
- `Agent.md` 验收命令写 `algorithm/integration/samples`，与默认合成目录不同；已在 README 写明这是联调样例，评测默认不读它。
- 笔数错归因需要逐行置信度，图片型 PDF 才具备；电子件恒判 `parsing`。
- `--strict` 目前等价「有失败即返回 1」，未来接 CI 时可加覆盖阈值。

## 裁决

- 伪造件按子集判、干净件按零容忍判：前者避免检测增强后反而「判错」，后者保证误报不被稀释。
- 归因只到六类，不再细分到具体检测项；具体项由证据里的 `rule_code` 表达，避免归因口径与规则集耦合。
- 报告不带时间戳与随机字段，评测结果可逐字节比对；时间信息交给调用方或 history。
- 评测入口与造数入口分开：`samples` 负责生成/校验，`eval` 负责跑分，互不隐式重建（`--build` 才重建）。
