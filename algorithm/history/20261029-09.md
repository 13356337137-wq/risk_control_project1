# 2026-10-29 · 09 · 报告聚合

## 意图

完成 AL-13「报告数据聚合」，把五态结论、四层结果、40 项指标、月度趋势、阈值提示与证据组装成 contract 报告结构，并保证缺交易号时不编造。

## 改动

- `metrics.py`
  - 新增 `MonthlyFlow` 与 `MetricSet.trend`，按覆盖月输出 `{month,income,expense}`；收入用剔除后入账，支出用全部出账。
- 新增 `algo/thresholds.py`
  - `ThresholdConfig`：DTI 0.5、收入变异系数 0.5、最低余额 1 倍月供、网贷平台 3 个、涉赌 1 笔、夜间 0.1，版本号默认 1。
  - `evaluate_thresholds()` 输出 `{code,level,threshold,value}`，只列触发项，`level=info`；未传 hits 不判涉赌；未传月供用 B01 近似并写入 notes。
- 新增 `algo/report.py`
  - `Report` 按 contract 输出 12 字段：carrier、verdict、verdict_reason、limitations、layers、metrics、metric_set_version、threshold_version、conclusions、trend、evidence、version。
  - `layers` 输出四层数组 `{layer,status,detail}`；`evidence` 按 `(rule_code,page_no,row_no)` 去重，`txn_id` 由 `transactions + txn_ids` 的页行映射填充，缺失时 null 并加「交易号未落库」。
  - `build_report()` 合并五态 limitations 与阈值说明，`version` 必须 ≥1。
- `algo/__init__.py` 导出 `build_report / Report / ThresholdConfig / evaluate_thresholds` 等。
- 新增 `tests/test_report.py`（11 项）；更新 `tasks.md`、`algo/README.md`、`chat.md`。

## 遗留

- contract 说 `layers` 是数组，mock 样例是对象；contract 报告结构没有 `task_id`，mock 有。当前按 contract 输出数组、不带 `task_id`，待 PM/PD 统一。
- `conclusions.level` 契约未定义取值，暂用 mock 的 `info`。
- 最低余额阈值的「当地月供」没有数据源，当前用 B01 月还款近似并注明；银行给了月供/地区参数后再切换。
- 报告 `version` 由调用方传入，自增与历史只增不改依赖后端落库；`txn_id` 也只能等 `txn` 表落库后全部回填。
- 涉赌阈值依赖 `detect_hits()`；不传 hits 时报告只写「未判定」，不会把 null 当 0。
- 外部层仍未实现，所以真实样本四层里 external 为 skipped，结论封顶为核验受限。

## 裁决

- 报告以 contract 字段为准，mock 只作展示参考；冲突处写进 chat 待 PM/PD 裁决，不在算法侧自创字段。
- 阈值只产生提示结论，不参与五态；五态仍由四层核验证伪决定。
- 趋势口径固定：收入剔除、支出原始；与 C01 的「A01 − 全部出账」保持一致。
- 证据必须能回到页、行、坐标；交易号未知时保留页行并注明，不编造 ID。
- 报告版本与指标/阈值版本分离：report.version、metric_set_version、threshold_version 三个号各管各的，只增不改。
