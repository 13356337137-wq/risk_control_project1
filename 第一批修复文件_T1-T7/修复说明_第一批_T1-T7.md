# 智能风控 · 信贷项目 第一批修复说明（T1–T7）

本次修复覆盖第一批「模板与标注体系」全部 **7 项 P0 级问题**，共修改 **11 个源码文件**，所有文件均保持原仓库相对路径，可直接覆盖到项目根目录使用。

## 一、逐项修复明细

### T1｜修复 `错位截屏.png` 框选与预读坐标错位
- **修改文件**：
  - `backend/routers/templates.py`（`_extract_meta`、`probe_template`）
  - `frontend-admin/src/lib/api.ts`（`ProbeSuggestion` 类型）
  - `frontend-admin/src/lib/fields.ts`（补齐 `channel`、`counterparty_name`、`reference_no` 中文映射）
  - `frontend-admin/src/pages/Annotate.tsx`（`adoptProbe`）
  - `web/src/components/annotate/CanvasStage.tsx`（列带渲染起止高度与最小宽度）
- **修复内容**：
  1. `probe_template` 修正 `boundaries` 相邻列分界计算，为每个建议列新增真实归一化区间 `col_x` / `col_w` 与点坐标 `x0` / `x1`（保留旧 `x` / `y` 兼容）。
  2. `_extract_meta` 新增 `header_y` 参数，仅在表头上方页眉区按行检索并合并同一正则命中的全部词外接框，消除「账号只框到卡号两字」「交易期间被截断」「表格首行人民币误判为页眉币种」三类错框。
  3. 旧版 `adoptProbe` 改为优先消费 `col_x` / `col_w` 与 `probeResult.table_area` / `header_y`，不再把表头中心点当左界、不再写死 `0.07` 宽与全页表格区。
  4. 新版 `CanvasStage.tsx` 列带改为从表头基准线 `headerY` 下方起算并保留至少 `3%` 可视宽度。

### T2｜打通前后端字段名断裂（`counterparty_name` vs `counterparty`）
- **修改文件**：
  - `algorithm/ocr/table.py`（新增 `canonical_field`、`FIELD_NAME_NORMALIZE`，接入 `apply_template` 与 `build_columns`）
  - `algorithm/ocr/parse.py`（`_KNOWN_FIELDS` 与 `_transactions_from_pages` 双键兼容）
  - `rc_platform/capabilities/parse_v2/table_reader.py`（`_row_from_cells` 双键兼容）
  - `backend/services/template_parse.py`（`build_template` 归一化 `field_map`）
- **修复内容**：将新版前端写入的 `counterparty_name` 与解析主链路内部标准名 `counterparty` 全面打通，确保对方户名正确写入交易主字段而不再丢失或误落入 `txn.extra`。

### T3｜防止页眉单值框（`meta_boxes`）在主解析链路被提前裁掉
- **修改文件**：`algorithm/ocr/parse.py`（`_clip_for_page`、`_fitz_extract`、`_transactions_from_pages`）
- **修复内容**：
  1. `_clip_for_page` 在首页（`page_no == 0`）保留顶部页眉区（`y0 = 0`），并在任意页自动将裁剪区扩张至覆盖该页全部 `meta_boxes`。
  2. `_transactions_from_pages` 在 `_crop_by_layout` 之前保留未裁剪的 `raw_words`，`_page_header` 与 `_fill_header_from_boxes` 均基于未裁剪词提取，保证卡号、户名、开户行、账户类型稳定命中。

### T4｜恢复模板回收站（`GET /templates` 补齐 `deleted_at`）
- **修改文件**：`backend/routers/templates.py`（`list_templates`）
- **修复内容**：返回字典补齐 `"deleted_at": t.deleted_at.isoformat() if t.deleted_at else None`，前端回收站页签筛选与「恢复」操作恢复正常。

### T5｜统一多页槽位枚举（`middle`/`auto`）并取消多页列几何拍平
- **修改文件**：
  - `algorithm/ocr/parse.py`（新增 `_layout_table_for`，`_layout_area_for` 委托调用）
  - `algorithm/ocr/table.py`（新增 `_pick_layout_table`，`build_columns` 支持 `page_no` / `total_pages` / `target_table`）
- **修复内容**：全面兼容 `first / second / middle / last / auto` 五种槽位；每页按当前匹配表格独立提取列几何，不再将多页不同列宽全局拍平到首页。

### T6｜临时模板补全 `layout` 并在用后 / 普通重跑时清空 `field_map_override`
- **修改文件**：
  - `backend/services/task_runner.py`
  - `backend/routers/tasks.py`（`reanalyze_task`）
- **修复内容**：
  1. `marks` 形式临时覆盖补调 `tlayout.build_layout(...)` 生成并传入 `layout`。
  2. `task_runner` 消费完一次性 `field_map_override` 后将其置空并在 `check_result.reparse` 记录 `consumed: true`。
  3. `reanalyze_task` 普通重跑或切换正式模板重跑时显式清空 `task.field_map_override = None`，并移除未使用的死变量。

### T7｜将画布表头基准线 `headerY` 接入主解析兜底链路
- **修改文件**：
  - `algorithm/ocr/table.py`（新增 `build_columns_from_layout`）
  - `algorithm/ocr/parse.py`（`_transactions_from_pages`）
- **修复内容**：当某页表头 OCR 乱码导致 `find_header` 未命中、但模板提供了当前页 `columns` 与 `headerY` 时，直接以 `headerY * page_h` 为表头下沿并按模板列框解析交易行，不再整页跳过；同时过滤 `headerY` 之上的噪声行。
