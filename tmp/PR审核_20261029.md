# 四、PR #2 上传页面

## 做得好的

1. **四条前端红线全守住**：无判断、无结论、无指标、无金额运算。
2. **明确写了「实际载体类型、清晰度和文件完整性以后端检查为准」** —— 与 contract「服务端判定载体，不接受客户端自称」完全一致。
3. **三类载体的文案分层**：电子件推荐、图片可人工复核、截图可能无法作为授信依据。业务口径准。
4. **竞态处理**：`selection.current` 递增，避免慢速检查覆盖新选择。这个细节很多人不写。
5. **拖入多个文件直接拒绝并给原因**，不是默默取第一个。
6. **诚实标注未接入**：按钮禁用、写明「文件只在本地检查，不会发送至服务器」。
7. vite 代理指向 127.0.0.1:8000，与 #1 的连接方式对得上。

## 阻断项（必须改）

### B1　期间字段与契约不一致

页面用 `type="month"`，提交值形如 `2026-04`；而 contract 的 `period_start / period_end` 是 **DATE**（`YYYY-MM-DD`）。

后果：接上传接口时前端传月、后端按日期解析，必然报错或静默截断。

处理（二选一，需 PM/PD 定，因为要改 contract）：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A | 契约改为接受 `YYYY-MM`，后端取月首与月末 | 接口语义变模糊，边界日不好表达 |
| B | 前端提交时补成月首日与月末日（`2026-04-01` / `2026-04-30`） | 前端要知道月份天数，但契约不变 |

我倾向 B：契约不动，前端做一次明确转换，并在页面提示「按整月提交」。

### B2　与 #1 的 startup.md 必然冲突

已用 `git merge-tree` 预演确认：两个 PR 都改了填写区同一行，合并必冲突。

处理：先合 #1，再让 #2 rebase 后把自己的身份行叠上去；或改框架（见第六节）。

## 缺陷（建议改）

### D1　格式判定依赖浏览器给的 MIME

当前判定是 `type === 'application/pdf' && 名字以 .pdf 结尾`。部分 Windows 环境或从网盘下载的文件，`file.type` 会是空串，合法 PDF 会被判成「仅支持 PDF、JPG…」而拒掉。

建议：**以扩展名为主判据，MIME 只作辅助**（MIME 为空时放行到后端再判）。后端的「看文件头不看扩展名」才是真正防线，前端不必抢这个职责。

### D2　配置不一致

| 项 | 现状 | 问题 |
| --- | --- | --- |
| vite host | config 写 127.0.0.1，script 写 `--host 0.0.0.0` | script 覆盖 config，两处说法不同 |
| plugin-react | 放在 dependencies | 构建期依赖，应在 devDependencies |
| tsconfig.app.json | 无 `composite` 字段 | `tsc -b`（build 模式）通常要求 `composite: true`，存在报错风险 |

### D3　装了没用

`react-router-dom` 已进依赖但尚未接路由。预览阶段可接受，但请在 tasks 里挂着，避免变成「装了就算做了」。

### D4　一条会变成谎话的提示

「文件只在本地检查，不会发送至服务器」在接入上传后就是错的。建议现在就挂一条任务：**接入上传接口当轮必须删除该提示**，否则线上会误导用户以为没上传。

# 六、框架级问题（建议这轮就定）

**startup.md 不适合入库。**

它的语义是「当前处理人」，天然是本地状态；入库后，两个人并行开工就冲突，且合并后只保留最后一个人的身份，历史信息全丢。

三个选项：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A | 加入 .gitignore，改用 `startup.local.md` | 零冲突 | 新人 clone 后没有模板，易漏填 |
| B | 拆成 `startup/<角色>.md`，各写各的 | 不冲突，可追溯 | 多四个文件 |
| C | 保留单文件，但规定「只在本地改、永不提交」 | 改动最小 | 靠自觉，容易误提交 |

我倾向 **B**：与「各部分一个文件夹」的结构一致，且能看出谁在哪一轮做了什么。
