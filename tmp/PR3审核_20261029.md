# 四、必须裁决的三项 P0（阻塞 DA-02）

## P0-1　明细缺证据三件套（坐标、置信度、剔除原因）

契约 `txn` 现有字段：`id、task_id、account_id、txn_date、direction、amount、balance、summary、counterparty_name、page_no`。

缺三样，各有硬业务依赖：

| 缺什么 | 谁依赖它 | 缺了会怎样 |
| --- | --- | --- |
| `coord_x / coord_y` | 报告证据跳转、模板标注对齐 | `report.evidence` 里有 x/y，但那是报告级 JSON，无法按笔查询；「结论能点回原页」只能存不能查 |
| `confidence` | 内容层归因（低置信先重跑，正常才判数据断） | 归因规则无法落库，每次重跑结论可能不同 |
| `drop_reason` | 六类剔除规则的留痕 | 「为什么这笔不算收入」答不出来，F06 的剔除规则无法审计 |

建议：`txn` 增四列（`coord_x`、`coord_y`、`confidence`、`drop_reason`），并在契约变更日志记一条。

## P0-2　appeal 表归属为空

异议申诉功能已从需求与产品设计中删除（借款人看不到结论，无从对结论提异议）。契约仍留 `appeal` 表。

三个选项：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A | 删除该表，十一表变十表 | 要改 proposal 的「十一表」表述 |
| B | 改定义为「银行侧疑义复核」 | 要补业务流程，目前没有 |
| C | 保留但不启用 | 表建了没人用，最容易被误用 |

我倾向 **A**：功能已删，表就不该留；表格数量本身不重要，「每张表都有人用」才重要。

## P0-3　报告版本字段未落库

契约报告结构有 `metric_set_version`、`threshold_version`、`conclusions`，但 `report` 表字段是 `id、task_id、version、carrier、verdict、layers、limitations、evidence`。

后果：F13 要求「改了阈值，老报告不重写、仍按当时版本解释」——版本号不进库，这条就无法实现，只能靠接口临时算，一重算就变。

建议：`report` 增 `metric_set_version`、`threshold_version`，`conclusions` 与 `layers` 同位（JSON 或另表，随 Q07 定）。
