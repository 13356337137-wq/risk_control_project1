## 一、真实性的可落地检测（只针对完好 PDF）

### 1. Acrobat / 编辑器改字留下的痕迹

| 痕迹 | 怎么查 | 成本 |
| --- | --- | --- |
| 增量更新 | 文件末尾出现第二个 EOF 标记（Acrobat 保存即追加） | 极低 |
| 修改日期不符 | CreationDate 与 ModDate 不一致 | 极低 |
| 生成器变了 | Producer 从银行报表系统变成 Adobe Acrobat | 极低 |
| 字体不一致 | 银行件字体全部嵌入子集，改字会新增未嵌入字体 | 低 |
| 视觉与文字层不符 | 渲染成图再比对文字层 | 中 |

### 2. AI 仿造（PDF 库合成 / 图生 PDF）的特征

| 特征 | 说明 |
| --- | --- |
| 无文字层，或文字层是 OCR 出来的 | 字的存储顺序混乱、一字一对象 |
| Producer 为 reportlab / fpdf / weasyprint / Chrome | 一查即知 |
| 字体是 Helvetica、Times 且未嵌入 | 银行件从不这么干 |
| 元数据几乎为空 | AI 工具不写 XMP |
| 无电子印章签名域 | 真件常带 |

> 结论：只收完好 PDF，AI 生成件在第一道闸就会被挡掉大半。

### 3. 数学勾稽（不依赖造假知识）

四道：逐笔余额链连续、明细求和等于合计行、笔数等于页脚「共 N 笔」、期初加收入减支出等于期末。
造假者要四条同时做对，等于把整份流水重算一遍。

两条等式与容差：
+ 期初 + 收入合计 − 支出合计 = 期末
+ 上笔余额 + 本笔金额 = 本笔余额（容差 0.01 元，同一秒多笔按序）

**反向修复**：某笔金额错一位导致余额对不上时，余额可反推正确金额——这是余额连续性最大的价值，不只是校验，是纠错。

### 4. 语义合理性规则（无需训练）

摘要格式的规律性（跨行转出-张三-尾号1234 格式漂移即可疑）、整数金额占比异常、时间分布异常（凌晨连刷）、收入支出比例不合理。

## 二、PDF 解析的固有难点

**PDF 里文字的存储顺序不等于视觉顺序。** 同一行的字可能存成若干互不相邻的对象，视觉位置全靠坐标。因此解析器必须**按坐标重建行列**，不能按存储顺序读。这是电子 PDF 解析最容易翻车之处，也是"完好 PDF"不等于"好解析"的原因。

## 四、时效性的行业惯例（检索所得）

+ 贷款普遍要求 3–6 个月流水，房贷常见 6 个月。
+ 银行不认"快进快出、即存即取"和"自存流水"。
+ 手机银行可打印 5 年内明细 → 用户可能上传多年前流水，因此**模板库必须保留历史版式**。
