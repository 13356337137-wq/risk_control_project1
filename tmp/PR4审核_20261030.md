## 三、阻断项（合入前必须解决）

### A1【阻断】本地 OCR 违反冻结项 F14 与 Agent.md:44，且未走解冻流程
- 证据：`forbidden.md` F14「抽取统一调行内 OCR 服务，不本地另搭识别」；`algorithm/Agent.md:44`「抽取只走行内 OCR 服务……不本地另搭识别模型，不把样本发到公网——数据不出行是硬约束」；PR 新增 `algorithm/ocr/engine.py:13,39`（RapidOCR 1.4.4 + 200DPI 渲染），`algorithm/ocr/README.md` 明写「影像件用 RapidOCR」。
- 事实：`forbidden.md` 的「解冻记录」里没有 F14；PR 只在 `algorithm/chat.md`「当前阻塞」里写「待组长/PM 确认」，即**先实现、后请示**。
- 业务影响：数据不出行是合规红线；且 OCR 口径一变，电子件/影像件走两套识别源，抽取可信度（design 第六节 X3）失去统一基线。
- 处置：二选一——① PM/PD 在 forbidden.md 正式解冻 F14 并同步修订 Agent.md:44（写明本地引擎、离线部署、模型随包）；② 保留适配层，默认实现改为调行内服务接口，RapidOCR 只作无服务时的显式降级（并在 limitations 标注）。

### A2【阻断】基于过期 dev，报告缺 `materials`，与主线契约不一致
- 证据：PR base 是 `dev`(a80f3fa)，该分支落后 `main` 41 个文件；主线 `contract.md`「报告结构」已因补件 `task_file` 变更新增 `materials`（{file_id,role,pages,sha256}，role=original/supplement），而 `algorithm/algo/report.py:36-50` 的 Report 只有 12 字段，实测序列化无 materials。
- 加重：`algorithm/tasks.md` 把 AL-13「聚合 JSON 符合 contract 报告结构」勾成 `[x]`，属于**按旧契约自评通过**。
- 业务影响：报告无法说明「本次结论依据哪几份材料」，补件场景（原件+补件）在报告里不可追溯；违反 F10（报告结构冻结）。
- 处置：先把 `main` 合入本分支（`git merge-tree main pr-4` 实测无文本冲突），再按新契约补 `materials`，字段来源（后端 task_file）与后端约定后写入 Report。

### A3【阻断】「回不到原页的结论不许出」未守住：页级证据写 (0,0)、证据 txn_id 允许 null
- 证据：`algorithm/Agent.md:48`「每条判断必须能给出交易号、页码、坐标；给不出就不进报告」；`algorithm/algo/evidence.py:12-16,28-34` 在 bbox 缺失时写 `x = y = 0.0`；实跑 eval 输出 `F3 第 1 页 行 - (0.0, 0.0)`；`report.py:29-33` 的 `txn_id` 为 `int | None`。
- 业务影响：审批人点「证据」会落到页面左上角；截图件的「来源可疑」甚至不带任何证据（`verdict.py:117` 取 file 层证据，而截图件 file 层为空）。
- 处置：无 bbox 时输出页级区域或明确 `coordinates_available=false`（不进「坐标」语义）；截图件给出页集合；契约补 evidence 坐标单位/可选性定义。

## 四、应改（不阻断，但会影响联调与业务口径）

### B1 证据坐标单位随抽取路径不同，且契约未定义单位
- 电子件：PyMuPDF 词框 = PDF pt（72dpi）；影像件/无文字层 PDF：RapidOCR 词框 = 200DPI 渲染像素（`ocr/engine.py:13,63,114-122`），`parse()` 两条路径都直接当 `Word.bbox` 使用，无换算。
- 影响：同一份报告里 x/y 含义差约 2.78 倍，前端「点回原页」在影像件上必偏；`contract.md` evidence 未写单位。
- 处置：统一换算到 pt（或相对页面比例）并写进契约；契约加一行「x/y 单位」。

### B2 影像件在 8 项图像取证（AL-18）未实现时仍输出「未发现异常」
- 证据：`file_layer.py:563-564` 对非电子件直接 `_empty("载体为 {carrier}，不做结构取证")`；`verdict.py:100-101` 只追加一句「影像件，核验受限，需人工复核」就继续走「未发现异常」。
- 契约 F12：影像件上限「未发现异常 + limitations + **图像取证 8 项**、强制人工复核」。8 项没做时，仍给「未发现异常」偏乐观。
- 处置：AL-18 落地前对 image 载体显式封顶（如只到「无法判定」或单列限制码），并要求后端强制人工复核。

### B3 外部层不一致 →「存在不一致」是 design 五态表未列的新触发条件
- 证据：`design.md` 第七节「五态结论怎么合」只有 6 行（载体/内容/账务/不可算/全通过/抽取失败），没有外部层；`algo/README.md:101` 与 `verdict.py:162-169` 却把 external fail 直接判「存在不一致」。
- 影响：五态是契约枚举，扩展触发条件属于口径变更，前后端与审批人认知会不一致。
- 处置：design 第七节补一行（外部层不一致 → 存在不一致/或按「线索」处理），并请 PM/PD 确认；同步 chat.md 裁决记录。

### B4 集成测试被 pytest.ini 排除，「174 passed」不含 OCR 集成
- 证据：`algorithm/pytest.ini` 只有 `norecursedirs = integration`；`tests/integration/test_rapidocr_engine.py`、`test_ocr_pipeline.py` 因此永不进入默认测试；本机跑 `tests/integration` 直接 3 failed（缺 rapidocr）。
- 影响：PR 描述「单测 13 + 集成 3 通过」无法由 `pytest algorithm/tests -q` 复现；OCR 这条最可疑的链路（F14）刚好被排除在 CI 之外。
- 处置：去掉 norecursedirs，集成测试用 marker 标记 + `skipif(依赖缺失)`，CI 单独跑真实引擎用例。

## 五、建议（可后续跟进）

1. **阈值结论 level 与结论码未进契约**：contract `conclusions` 只写 {code,level,threshold,value}，未定义 level 取值；13 个结论码（DTI_HIGH…CRYPTO_HIT）也不在 rule 表/契约里。后端落库与前端展示的枚举来源缺失（chat.md 已自记）。
2. **`by_code` 会抛 KeyError**（`metrics.py:108-112`，`thresholds.py:90-91`）：传入不完整指标集、或将来按 design 第八节「停用指标」时会直接崩掉报告生成，建议缺项返回 None。
3. **limitations 出现英文层名**：`verdict.py:108` 生成「external 未执行」，与契约示例的中文文案风格不一致。
4. **dev_steps.py** 是 note 风格一次性脚本，依赖未入库的真实样本（`inputs/samples/icbc_desensitized.pdf`），新环境跑不通；建议移到 docs 或删除。
5. **eval 6/6 是合成样本自证**（作者已在 README 声明）：design 第十节 V2（10 份真件误判≤1）、V3（抽错归因）仍无真实数据，不能当验收证据。
