# 项目与业务需求差距分析（业务口径）　2026-10-30

> 读法：不谈代码，只谈「一笔真实业务进来，系统能不能接住」。
> 依据：仓库当前状态 + 需求分析、产品设计、契约；每条差距都写清业务后果和责任方。

# 一、一句话结论

**现在像一间样机展台，不像一条能开业的流水线。**

零件基本都在：能拍照上传、能框选版式、能算出 40 项指标、能跑出五态结论。
但**没有一条线把它们串起来**——材料进不了系统，报告出不了银行台面，出了问题查不到人。

全链路七个环节，真正能用的约 **1.5 个**（模板标注 + 解析内核）。

# 二、按业务全链路逐步对照

| 环节 | 业务上要做什么 | 现在能答吗 | 差距（业务后果） |
| --- | --- | --- | --- |
| 1 收件 | 客户交材料，系统当场告诉他要不要补、缺什么 | **不能**：上传页只能在本机试选文件，按钮是灰的，没有任何一处能真正收下材料 | 系统没有入口；客户只能线下交，全部流程回到人工 |
| 2 过门槛 | 判断是不是能处理的材料（格式、加密、图清不清楚、装订混不混） | **不能**：规矩写好了，但没有一处执行 | 收到糊图、加密件、混装件也照样往下走，后面全白跑 |
| 3 读内容 | 把纸面变成可算的数（账号、期间、每笔明细） | **部分能**：解析内核跑得通，但只在样品上验证过；按版式取数的模板抽取还没接上 | 客户拿来的他行流水大概率读不准，指标就不可信 |
| 4 验真假 | 四层核验：材料本身 → 内容自洽 → 账务反算 → 外部 | **部分能**：电子件结构取证有 11 项；**影像件 8 项取证一项没做**；账务反算缺利率就跳过；外部核验是空壳 | 拍照件的结论不可靠；「未发现异常」可能给错 |
| 5 算指标 | 40 项指标、剔除规则、缺数据要说清 | **能**：40 项齐、六类剔除、缺值写说明 | 这一环最扎实，但它的输入（明细）不稳，结果仍不可用 |
| 6 出结论 | 五态结论 + 阈值提示，且能说明凭什么 | **部分能**：五态能合成、阈值能判；**结论常常回不到原页**（证据位置是页面左上角） | 审批人无法复核，等于让他盲签 |
| 7 出报告 | 只给银行看的一份报告，说清依据了哪几份材料 | **不能**：报告能生成，但没有界面能看；补件后「依据了哪几份材料」刚补上，还没联起来 | 报告出不了银行台面，审批人拿不到 |

**断点在第 1 步**：材料进不来，后面做得再好也只能演示。

# 三、三类使用者分别缺什么

## 借款人（客户）

| 他需要 | 现在 |
| --- | --- |
| 上传能成功、能看到「收到了」 | 只有页面预览，点了没反应 |
| 知道缺什么、怎么补 | 没有进度页、没有补件页 |
| 知道材料会被怎么用、留多久 | 页面没写 |
| 绝不看到结论与指标 | 这一点守住了 ✔ |

## 审批人（业务主力）

| 他需要 | 现在 |
| --- | --- |
| 打开就有待办 | 没有工作台 |
| 一份报告：结论、四层结果、指标、证据 | 只有两个「示例数据」演示页，不接真实结果 |
| 点证据能跳到原页原行 | **跳不了**：坐标是 0,0 |
| 影像件必须人工复核的强制动作 | 规则写了，系统没拦 |
| 复核意见留痕 | 没有复核页，无从留痕 |

## 模板管理员

| 他需要 | 现在 |
| --- | --- |
| 把长尾版式录进来 | **能**：框选、指定字段、自建字段、导出（本轮交付） ✔ |
| 存下来、发布、停用 | 不能：存不进库里，也没有版本列表 |
| 录完立刻验一下抽得对不对 | 不能：只有演示用的假结果 |
| 样本原件怎么存、谁能看 | 没定：样本是客户真件，这是合规口子 |

# 四、六个「业务上会出事」的点

| # | 风险 | 业务说法 |
| --- | --- | --- |
| 1 | 材料进不来 | 系统没有收件窗口，整个项目无法产生一笔真实任务 |
| 2 | 证据回不到原页 | 审批人看到结论却点不到出处，等于让他相信一句没有依据的话 |
| 3 | 拍照件没做图像取证却可能给「未发现异常」 | 一旦出事，银行无法解释为什么放过了一张 P 过的图 |
| 4 | 补件后报告说不清依据哪几份材料 | 客户说「我补过」，银行拿不出证据 |
| 5 | 没有留痕与权限 | 审计会问：谁看的、谁改的、谁签的；现在答不出 |
| 6 | 「数据不出行」还没定论 | 现在的识别引擎在本地跑，形式上与行内规定不一致，需正式裁决 |

# 五、一笔真实业务会断在哪

```text
客户来交流水 →【断】系统没有收件入口，只能线下收
              ↓ 假设人工塞进去
系统判断材料合格 →【断】没有这道闸
              ↓ 假设人工把关
机器读明细 → 他行版式没模板 → 读不准
              ↓ 假设凑合读出来
核验真假 → 拍照件缺 8 项取证、外部核验没开 → 只能给「无法判定」
              ↓
算指标 → 能算
              ↓
出结论 → 证据坐标是左上角，回不到原页
              ↓
出报告 → 没有界面能打开
              ↓
审批人签字 → 只能凭人工再看一遍原件
```

结论：**今天的系统能证明「技术路线可行」，还不能支撑「一笔业务走完」。**

# 六、差距分级

| 级别 | 含义 | 包含 |
| --- | --- | --- |
| A 能演示 | 给领导看流程走得通 | 上传页预览、模板标注、真伪判定示例、指标报告示例 |
| B 能试点 | 一笔真实业务能走完并留痕 | 收件与过门槛、模板存取与发布、解析接模板、报告页、复核与留痕、权限 |
| C 能生产 | 可对外承诺准确率与合规 | 影像件 8 项取证、外部核验、真实样本验收、留存与脱敏、审计与监控 |

现在：A 基本齐；B 缺 6 件；C 缺 5 件。

# 七、三阶段建议（业务承诺什么）

| 阶段 | 目标 | 对外能承诺 | 主要缺口 |
| --- | --- | --- | --- |
| 第一阶段：演示版 | 一条样板流水从上传到报告全程走通 | 「流程已打通，准确率待真实样本验证」 | 收件入口、报告页、模板存取 |
| 第二阶段：试点版 | 一家行、一种版式、人工复核兜底 | 「单版式可跑，结论必须人工复核」 | 模板抽取、复核留痕、权限 |
| 第三阶段：生产版 | 多版式、拍照件可用、可审计 | 「按规则出具结论，可追溯」 | 图像取证、外部核验、真实样本验收 |

# 八、需要业务方现在拍板的五件事

| # | 事项 | 不定的后果 |
| --- | --- | --- |
| 1 | 第一版只做哪种材料（电子件优先？） | 什么都做，什么都做不深 |
| 2 | 拍照件在图像取证做完前，结论封到什么程度 | 可能给出偏乐观的「未发现异常」 |
| 3 | 模板由谁来录、样本原件怎么保管 | 合规口子，审计必问 |
| 4 | 数据不出行的具体要求（能否用离线引擎） | 算法方向卡住，报告写不出限制说明 |
| 5 | 试点阶段的验收标准（多少份、错几份算通过） | 永远「快好了」，无法宣布可用 |

# 九、这份分析没覆盖什么

- 没做真实样本验证，所以「读得准不准」目前只有合成样本证据。
- 没做性能与容量评估（一天多少笔、峰值多少）。
- 没做与行内系统的对接评估（客户信息、影像平台、信贷系统）。
