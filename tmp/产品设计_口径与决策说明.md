# 产品设计 · 口径与决策说明（内部，不随文档交接）

以下内容从《产品设计文档》中移出：它们解释"为什么这样设计"，是给负责人看的，不是给开发照着做的。

## 一、真实性核验三步的顺序依据

顺序按证据强度排：数字核对最强但不防高级伪造，结息能防伪造但依赖利率表，痕迹最弱且易被银行改版误伤。所以前两项任一失败即停止，第三项异常只降级不阻断。

## 二、数字核对为什么并入核验而不单列

它是核验的一步，逻辑上没有独立地位。并入后仍要保留归因：四项算术失败时，必须先看该行抽取置信度，置信度低是解析问题，回解析重跑；置信度正常才判数据断。

归因一旦丢失，我们的解析缺陷就会被写成客户的材料问题。这是并入时最容易丢的东西。

## 三、数据模型的刻意取舍

| 取舍 | 说明 |
| --- | --- |
| 校验结论存 JSON | 四条结论只与任务一一对应，不按校验项查询，无需建表 |
| 报告证据存 JSON | 证据随报告读取，不按交易反查报告，省一张表 |
| 批次命中存 JSON | 命中只按批次整批查看，不做跨批检索 |
| txn 冗余 task_id | 冗余字段，省一次关联查询；按任务查是最热路径 |
| 模板与规则只增不改 | 历史任务引用的版本必须能读回来 |
| 借款人不成账号 | 无登录体系，姓名随任务固化 |



## 四、为什么不用菱形判断节点

mermaid 的菱形按外接正方形计算尺寸，文字仅两个字也会同时撑宽与撑高，行距被拉开，且与矩形节点难以对齐。压缩标签无法解决，只能换形状。

## 五、两条判断为什么不算风控

| 保留 | 为什么不算 |
| --- | --- |
| 材料真实性三态 | 判"东西是不是真的"，是事实判定，不说客户好不好 |
| 四项校验、解析自检 | 判"数据能不能用"，是质量判定，不涉及放不放款 |
