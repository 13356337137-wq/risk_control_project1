# FE-39 加密流水特殊情况（压缩包与口令）

## 意图

客户从手机银行导出的流水常是「带口令的 zip，里面一份 PDF」。收件时不能把它当损坏文件拒掉，也不能静默失败，要能识别、要口令、留痕。

## 改动

- `src/lib/archive.ts`：zip 识别与解包（zip.js）；无口令只读目录（`need-password`）；错误口令（`wrong-password`）；体积上限 200MB；损坏包转业务话术。
- `src/lib/pdf.ts`：PDF 口令支持（`PdfPasswordError`，区分「需要口令/口令错误」）。
- `src/components/PasswordDialog.tsx`：口令输入框，提示常见口令位置，显示剩余次数，明确「只在本机内存使用」。
- `src/pages/Annotate.tsx`：收件流程接入口令（zip → PDF 双层）、3 次上限、放弃话术、特殊情况事件面板。
- 样式：对话框与事件面板。

## 验证

用真实文件 `招商银行交易流水(申请时间2026年10月22日12时44分50秒).zip` 实测四条分支：

| 分支 | 结果 |
| --- | --- |
| 无口令 | `need-password`，包内文件名正确解码（GBK 未乱码） |
| 错误口令 | `wrong-password`，未误报损坏 |
| 空口令 | `need-password`，不崩溃 |
| 损坏包 | 「这不是有效的压缩包，或文件已损坏，请让客户重新导出」 |

构建：`tsc -b` 0 错；`vite build` 通过（主包约 399KB，含 zip 解包库）。

## 遗留

- 记录只在本机（事件面板），后端受理接口未实现（BE-33）。
- 招行模板未标，这份材料解包后仍会走通用兜底。
- 口令正确路径无法自测（不知口令），需客户输入后确认。

## 裁决

契约新增「特殊情况：压缩包与口令」（2026-10-30）：zip 不在受理格式内、口令最多 3 次、不落库不落日志、代解需标注与审计。受理政策 A/B/C 待业务方定。
