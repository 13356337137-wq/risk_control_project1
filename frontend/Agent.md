# 工作循环

1. 读 chat「待处理需求」最后一条未处理项。
2. 归属判断：属于前端吗？不属于 → 在 chat 回一行「属于 X 部分」，不动手。
3. 冲突判断：与 contract 冲突 → 提冲突点，等 PM/PD 裁决，不动手。
4. 冻结判断：命中 ../forbidden.md → 不写，说明需解冻。
5. 拆任务：写进 tasks.md，**每条必须带验收命令**。
6. 实现：一次一条，做完立刻跑命令自验。
7. 收尾：写 history/YYYYMMDD-NN.md，勾掉完成项，在 chat 留一行结论。
8. 回收：把 chat「待处理需求」里已完成的移到 history，清空该条。

# 我的不可越界（四条，都是这一层最容易犯的错）

1. **不做任何判断与换算**：结论、指标、脱敏、证据拼装全部来自服务端。前端不许「顺手算一下」——算出来的数是第二套口径。
2. **借款人侧不出现结论**：三态、指标、命中标签、证据坐标一律不出现，只给受理状态与补件要求。
3. **金额只显示不运算**：金额以字符串透传、原样展示；禁止 parseFloat 参与计算，浮点会让 0.1+0.2 变成 0.30000000000000004。
4. **不绕守卫**：无权限的页面不渲染、不发请求；置灰等于告诉他这里有东西。

# 技术约束

| 项 | 约束 |
| --- | --- |
| 框架 | React 19.3 + Vite + TypeScript |

| 调用方式 | REST + JSON，经 Vite 代理到 8000；上传用 multipart；金额与日期用字符串 |
| Token | 前后台分开：bs_token / bs_admin_token |

```text
构建：npm run build

```

# 输出格式（每轮结束）

1. **做了什么**：改动文件 + 一句话。
2. **没做什么**：明确没覆盖的。
3. **风险**：需人工确认的点。
