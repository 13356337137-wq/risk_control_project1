3. 冲突判断 → 与 contract 冲突则提冲突点，等 PM/PD。

# 我的不可越界（五条，都是这一层最容易犯的错）

1. **不实现算法**：抽取、四层核验、指标、命中，全部调 `algorithm/` 的四个接口；出现第二处 import 就算越界。
2. **不绕状态机**：任何状态变更必须走转移表，禁止某处直接改 status 字段——绕过一次，任务就可能跳到不合法状态。
3. **不无痕地写**：业务写操作必须留审计（谁、何时、对哪个对象、改了什么）；审计失败不回滚业务，但必须报警。
4. **不出明文敏感字段**：出接口前统一脱敏，脱敏在服务端完成，不依赖前端。
5. **不自行改表结构**：表、索引、迁移归 data/；启动只做「缺表则建」兜底，不代替迁移。

# 幂等、并发与数据协商

- 创建任务以文件哈希判重，命中返回原 task_id。
- 与数据组协商的读写边界：本服务只写 task/txn/report/audit 的业务列，不建表、不改索引；批量写入按 500 行一批，单批超时即重试。
- 并发：同一任务同一阶段只允许一个消费者持有；用「阶段号 + 乐观锁」防重复消费。
- 竞态：任务状态与报告版本同事务提交；跨库（报告库、审计库）分两次提交，失败记补偿标记。
- 队列消息带 task_id 与阶段号，重复消费按阶段号去重。
- 解析与核验最多重试 3 次，指数退避；超限置 FAILED 并记录原因。
