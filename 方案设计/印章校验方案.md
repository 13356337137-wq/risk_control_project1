# 印章校验方案（设计稿，未实现）　2026-10-30

> 背景：你提到印章比对是真实性校验的重要一环。本文件定设计与边界，代码尚未实现。
> 现状：两份实测样本（工行电子明细、招行 PDF）**都没有印章**，因此当前无法验证，需要盖章材料。

# 一、先说清印章能证明什么

| 能证明 | 不能证明 |
| --- | --- |
| 该页由某机构出具（章文与行名一致时） | 内容没被改过（章可被复制粘贴） |
| 电子签章覆盖范围内未被篡改（PKI 有效时） | 章本身是真的（图片章可 P） |
| 骑缝章能把多页绑定成一份（骑缝连续时） | 业务真实发生 |

**结论：印章解决「谁出的」，不解决「内容真不真」。所以印章是加分项，不能替代文件层与数据侧。**

# 二、三层校验

| 层 | 查什么 | 技术 | 结论上限 |
| --- | --- | --- | --- |
| 1 存在与完整 | 有没有章、是否缺角/遮挡/压字、位置是否合理 | 颜色分割 + 圆形拟合 + 边缘完整度 | 缺章 → 来源可疑 |
| 2 章面内容 | 行名、机构名、编号、章类型（业务章/财务章/公章/骑缝） | 印章文字识别（旋转校正后 OCR） | 章文与行名不一致 → 存在不一致 |
| 3 章比对 | 与真章模板是否同一枚；多页是否同一章；骑缝是否连续 | 文字一致性 + 图像相似度 + 位置/大小 + 骑缝拼接 | 相似度高 → 仅「未发现可疑」 |

# 三、检查项（拟编号 F13-F20）

| 编号 | 检查 | 不通过时 |
| --- | --- | --- |
| F13 | 印章存在性 | 应盖章材料无章 → 来源可疑 |
| F14 | 印章完整性 | 缺角/严重遮挡 → 核验受限 |
| F15 | 印章清晰度 | 模糊到无法识文 → 核验受限 |
| F16 | 章文与行名一致 | 不一致 → 存在不一致 |
| F17 | 章类型与材料类型匹配 | 明细盖公章属异常 → 提示 |
| F18 | 同份材料多页同章 | 不同章 → 存在不一致 |
| F19 | 骑缝章连续性 | 断裂 → 可能存在抽换页 |
| F20 | 电子签章 PKI | 签名无效/过期 → 存在不一致 |

# 四、比对怎么做（第 3 层）

| 手段 | 做法 | 局限 |
| --- | --- | --- |
| 文字比对 | 识别章文 → 与行名/机构词库比对（模糊匹配处理印章变形） | 变形严重时识别率下降 |
| 图像相似度 | 归一化后 ORB/感知哈希对比真章模板 | 需要该行真章模板库 |
| 位置与大小 | 章的直径、中心位置、与落款行相对关系 | 版式差异大时误报 |
| 骑缝 | 相邻页边缘章弧拼接比对 | 扫描错位会影响 |
| PKI | 验签 + 证书链 + 时间戳 | 仅电子签章有效，图片章无效 |

# 五、结论影响（与四层的关系）

| 情况 | 结论 |
| --- | --- |
| 应盖章材料无章 | **来源可疑（封顶）** |
| 有章但章文与行名不一致 | **存在不一致** |
| 章存在但模糊/遮挡 | 核验受限，不改变数据侧结论 |
| 章与真章模板一致 + 其余通过 | 未发现异常（印章本身仍不给「真」） |
| 电子签章验签通过 | 可将载体层 8 项中的签名项判为 pass |

# 六、隐私红线（关键）

你给的百度「印章识别」是**云端 API**。把客户流水上传给百度，等于把 L1 原件交给第三方——与我们已定的隐私方案直接冲突：

| 方案 | 是否可行 | 说明 |
| --- | --- | --- |
| 整份 PDF 传百度 OCR | **禁止** | 原件出银行，违反红线 |
| 只传印章裁剪图 | **不推荐** | 章图仍含行名与编号，且可反查账户 |
| 行内 OCR/印章识别服务 | **推荐** | 数据不出行内网 |
| 本地模型（PaddleOCR 等） | **推荐** | 离线，可批量；需准备印章训练/调优 |

落地顺序：先做**本地检测 + 本地识别**，行内有服务再切行内 API；**任何时候都不接公有云**。
