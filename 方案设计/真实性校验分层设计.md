# 真实性校验分层设计 v2（来源 / 文件 / 数据）　2026-10-30

> 定位：真实性校验是所有分析的地基。假数据算一万遍，只是把错误算得更精确。
> v2 在三侧各自展开检查项，并定义「最弱一环决定结论」的口径。

# 零、三条铁律

| # | 铁律 | 含义 |
| --- | --- | --- |
| 1 | **木桶原则** | 结论取三侧最弱一档，不允许用其他侧的良好表现补短板 |
| 2 | **不可算 ≠ 通过** | 没做的检查记为不可算，不得计入「未发现异常」 |
| 2b | **选填 ≠ 必填** | 唯一必填是流水文件；来源凭证等选填缺失只写受限说明，**不降结论档位** |
| 3 | **只给方向，不给鉴定** | 最强表述是「未发现可疑」，永不说「真实」 |

# 一、来源侧（谁出的、什么时候出的）

## 1.1 凭证类型库（全部选填，不填不影响受理）

| 凭证 | 出现在哪 | 实测样例 |
| --- | --- | --- |
| 验证码 | 招行流水页眉 | 「验证码 79EKKP7E」+ 官网交易流水验真 |
| 申请单号 | 工行明细标题 | 「申请单号 26101418224961978183」 |
| 二维码 | 工行页眉 | 「请扫描二维码识别明细真伪」 |
| 流水编号/回单号 | 建行、农行等 | 各行不一致 |
| 导出人/工号 | 柜台打印件 | 部分行有经办人 |
| 导出时间 | 多数行 | 招行「申请时间 2026-10-22 12:44:50」 |
| 导出渠道 | 手机银行/网银/柜台 | 与文件内标注比对 |
| 文件哈希 | 平台自算 | 用于行内留档比对，防「真壳假芯」 |

## 1.2 核验渠道

| 渠道 | 能核什么 | 限制 |
| --- | --- | --- |
| 官方在线验真（招行官网） | 录入基本项+明细项，返回是否一致 | 需人工，无法批量 |
| 行内系统比对（E5/E6） | 与行内留存原件或代发数据比对 | 需接入与授权 |
| 二维码解码 | 取参数走对应渠道 | 二维码也可伪造，不能单靠 |
| 客服/柜面函证（E2） | 大额存疑时人工核 | 慢、成本高 |

## 1.3 来源可信等级（决定结论上限）

| 等级 | 含义 | 对结论的影响 |
| --- | --- | --- |
| S0 | 未提供凭证、未核验 | **不降档**；报告写「来源未核验，建议补证」 |
| S1 | 提供了凭证、未核验 | 不降档；写「凭证已提供，待核验」 |
| S2 | 凭证经官方渠道核验一致 | 可写「来源已核验」，结论不变（仍受文件侧与数据侧约束） |
| S3 | 核验 + 行内留档哈希一致 | 可写「来源已核验且与留档一致」，仍不等于「真」 |

## 1.4 交叉校验（低成本、易被忽略）

| 交叉项 | 不一致说明什么 |
| --- | --- |
| 凭证导出时间 vs 明细期间 | 期间超出导出时点 → 被改过或换了期间 |
| 凭证银行 vs 文件表头银行 | 张冠李戴 |
| 账号 vs 凭证账户 | 调包 |
| 二维码/验证码 vs 文件哈希 | 真壳假芯 |
| 导出渠道 vs 版式 | 手机银行渠道却是柜台版式 → 可疑 |

## 1.5 能证明 / 不能证明

| 能 | 不能 |
| --- | --- |
| 该行在该时点生成过这份文件（核验通过时） | 文件没被改过 |
| 账户与期间与凭证一致 | 账户属于提交人（需身份核验） |
| | 内容未被替换（除非有哈希留档） |

# 二、文件侧 A：PDF 容器取证（12 项）

| # | 检查 | 看什么 | 强度 |
| --- | --- | --- | --- |
| F1 | 生产者/创建者 | 是否银行系统（招行实测 openhtmltopdf.com） | 中 |
| F2 | 创建/修改时间矛盾 | 修改早于创建、时间早于系统安装 | 中 |
| F3 | **增量更新** | PDF 允许追加修改；存在多次更新即被改过 | **强** |
| F4 | 交叉引用/对象异常 | 拼接、删页、重打包 | 强 |
| F5 | 字体嵌入与子集 | 后加文字字体不一致 | 中 |
| F6 | 页树与页面对象 | 页面被替换、顺序异常 | 中 |
| F7 | 注释/表单/隐藏层 | 藏内容、藏页、表单域篡改 | 中 |
| F8 | **数字签名与时间戳** | 签名覆盖范围被改即失败 | **最强** |
| F9 | 加密与权限位 | 是否禁复制/打印、权限被重置 | 弱 |
| F10 | 嵌入附件/脚本 | 夹带文件或 JS | 中 |
| F11 | 图像流参数一致 | 同页多图压缩参数差异 | 中 |
| F12 | 页尺寸/边距一致 | 拼页常尺寸不一 | 中 |

工行样本实测：8 页、旋转 90°、无签名、无元数据 → F1/F2/F8 全部不可判，报告必须写「无签名、无元数据，容器取证受限」。

# 三、文件侧 B：图片与图片型 PDF（12 项）

## 3.1 元数据/容器层（5 项）

| # | 检查 | 能看出什么 |
| --- | --- | --- |
| P1 | EXIF 设备与软件 | 扫描/拍照/截图，或编辑工具导出 |
| P2 | **双压缩痕迹（JPEG ghost）** | 图像被打开再保存过 |
| P3 | 量化表与压缩参数 | 同页不同区域参数不一 → 拼接 |
| P4 | 缩略图 vs 主图 | 不一致 → 图被换过 |
| P5 | 时间戳链 | 拍摄/修改/文件系统时间矛盾 |

## 3.2 像素层（7 项，必须做图像分析）

| # | 检查 | 能看出什么 |
| --- | --- | --- |
| P6 | **ELA 误差级分析** | 局部修补、贴图区域压缩响应不同 |
| P7 | 噪声一致性（PRNU/CFA） | 拼接区域缺相机噪声 |
| P8 | 重采样痕迹 | 缩放、旋转的插值残留 |
| P9 | **拼接边界** | 边缘不连续、双重边缘 |
| P10 | 光照与阴影方向 | 多处光照方向不一致 → 合成 |
| P11 | 摩尔纹/屏幕纹理 | 翻拍屏幕（与截图件区分） |
| P12 | 文字反锯齿与字距一致 | 后贴数字的渲染差异 |

**直接结论**：

> 图片或图片型 PDF，**文件与元数据层只能判断「容器被处理过没有」**；
> 「图像内容有没有被改」必须靠 P6–P12，而且只能给「可疑 / 未发现可疑」。
> 图片型 PDF 优先取**原始图像流**，渲染图会让二次压缩盖掉痕迹。

# 四、数据侧（24 项，四组）

## 4.1 结构自洽（6 项）

| # | 检查 | 说明 | 状态 |
| --- | --- | --- | --- |
| D1 | 余额链逐笔闭合 | 明细不能随便编 | ✅ |
| D2 | 页脚笔数 vs 解析笔数 | 是否被删笔 | ✅ |
| D3 | 每页合计 vs 明细求和 | 是否被改数 | ✅ |
| D4 | 期初期末 vs 首末笔余额 | 首尾是否被动 | ✅ 缺标注则不可算 |
| D5 | **序号连续性**（工行有「序号」列） | 插笔/删笔的硬证据 | ❌ 新发现 |
| D6 | 跨页连续性 | 分页处断行、重复行 | ❌ |

## 4.2 账务自洽（6 项）

| # | 检查 | 说明 | 状态 |
| --- | --- | --- | --- |
| A1 | 结息反算 | 余额×利率×天数 与记账利息比对 | ⚠️ 缺利率表 |
| A2 | 利息税 | 税后利息规律 | ❌ |
| A3 | 费用周期性 | 账户管理费/短信费 | ⚠️ 部分 |
| A4 | 到账时延/清算规律 | 跨行到账时间合理性 | ⚠️ 缺时间字段 |
| A5 | 方向与余额变动一致 | 方向被翻转立刻暴露 | ❌ |
| A6 | 金额精度与千分位一致 | 手工改数常破坏格式 | ❌ |

## 4.3 时间与行为（6 项）

| # | 检查 | 说明 |
| --- | --- | --- |
| B1 | 时间序列完整性 | 缺月、跳日、期间不符 |
| B2 | 重复交易检测 | 同金额同对手短时重复 |
| B3 | 交易时段分布 | 夜间/整点异常集中 |
| B4 | 摘要语义一致 | 「消费」却入账 |
| B5 | 对手方结构 | 掩码格式、同一人多账户、重复对手 |
| B6 | 资金快进快出 | 入账后短时等额转出 |

## 4.4 跨文档一致（6 项）

| # | 检查 | 说明 |
| --- | --- | --- |
| X1 | 多份互证 | 同账户不同期、同一人不同行（外部层 E6） |
| X2 | OCR vs 文本层 | 图片型 PDF 夹带文字层造假 |
| X3 | 模板命中与列语义 | 版式被改会立刻暴露 |
| X4 | 页眉页脚/字体/水印跨页一致 | 抽换某页 |
| X5 | 隐藏文字层/批注异常 | PDF 夹带 |
| X6 | 账户名与提交人一致 | 需身份核验 |

# 五、三侧输出与结论上限（木桶）

| 场景 | 结论 | 报告必须写明 |
| --- | --- | --- |
| 电子件 + 容器未见异常 + 数据全通过 | **未发现异常** | 受限项照写；来源未核验要写 |
| 电子件 + 容器异常或签名失效 | **存在不一致** | 触发项与证据坐标 |
| 任何载体 + 数据有断点 | **存在不一致 / 余额可疑** | 断点位置 |
| 截图件 | **来源可疑（封顶）** | 不得作为授信依据 |
| 影像件 + 像素取证未做 | **无法判定（封顶）** | 图像取证未完成，需人工复核 |
| 来源凭证未提供 | 不单独影响结论 | 「来源未核验，建议补证」 |

说明：来源侧是**加分项不是门槛**——只有流水文件必填，所以来源缺失不能把人判死。
截图件与影像件的封顶来自载体规则（F12），与来源凭证无关。

# 六、证据链硬要求

每条结论必须带：交易号（或页+行）、页码、坐标、触发它的检查项编号。给不出的，不进报告。
