# 流水数据隐私与外部调用方案　2026-10-30

> 回答一个问题：解析流水、以及调用 API 时，怎么保证客户数据不外泄、不合规。
> 现状依据：代码审计（算法与前端均无外网调用；无统一脱敏层；本地 OCR 为离线模型）。

# 一、先分清「数据」是哪一层

不同形态的敏感度差很多，处置手段也不同：

| 层 | 内容 | 敏感度 | 能不能出银行 |
| --- | --- | --- | --- |
| L1 原件 | 客户上传的 PDF/图片/压缩包 | **最高**（可比对、可截图、可再传播） | **绝对不能** |
| L2 文本层 | 从 PDF 抽出的整页文字（含姓名、账号、摘要） | 高 | 不能 |
| L3 字段值 | 账号、户名、证件、手机、每笔明细 | 高 | 不能（脱敏后视情况） |
| L4 派生结果 | 40 项指标、五态结论、提示项 | 中（可反推，但不含原文） | 脱敏/聚合后可，仍需审批 |
| L5 日志与审计 | 操作记录、尝试次数、错误码 | 低（前提是不含原值） | 可，但必须脱敏 |

**一句话原则：原件和文本层不出行；字段值脱敏后才谈传输；派生结果按需最小化。**

# 二、三种处理模式，风险完全不同

| 模式 | 数据去哪 | 隐私风险 | 可控手段 | 我们的建议 |
| --- | --- | --- | --- | --- |
| A 本地离线 | 不出机器 | 最低（只剩本机权限与留存问题） | 磁盘加密、访问控制、留存期限 | **第一版就用这个** |
| B 行内自建 API | 行内网内另一台服务 | 低（内部可控） | 网络隔离、服务鉴权、审计、不留存 | **目标形态** |
| C 外部云 API | 银行外的第三方 | **最高**（数据出境/出境相当于失控） | 合同约束 + 脱敏 + 不留存 + 审计 | 原则上不允许；确需时只放 L4 |

招行/工行导出件里包含姓名、卡号、每笔消费与对手方——**这类数据一旦发给外部 API，就等于把客户交给第三方**。所以：

1. 解析（OCR、表格识别）**只能走 A 或 B**。
2. 若将来引入大模型辅助，只能喂 L4（指标与结论），且必须先去标识化。
3. 任何 C 类调用必须能回答：发的是什么、发给谁、留多久、谁能看。

# 三、如果非要用外部 API，九条硬约束

| # | 约束 | 怎么落地 |
| --- | --- | --- |
| 1 | 只传派生数据 | 代码层限制：外发前序列化只允许 L4 字段白名单 |
| 2 | 先去标识化 | 账号留前四后四、姓名留姓、对手方按角色掩码、证件只传哈希 |
| 3 | 不训练 | 合同写明「不得用于模型训练/微调」，并要求供应商出书面承诺 |
| 4 | 不留存 | 合同写明请求即弃；技术上要求供应商提供「零留存」开关并验证 |
| 5 | 数据驻留 | 合同限定服务器所在地，禁止跨境；调用前记录请求地域 |
| 6 | 传输加密 | 强制 TLS，禁用明文 HTTP；证书校验不得关闭 |
| 7 | 最小化 | 每次只发本次必需字段；禁止整份流水上传 |
| 8 | 可审计 | 每次外发留痕：时间、字段清单、目的、操作人；不含原值 |
| 9 | 可一键关闭 | 配置项默认关闭，出事能立刻断掉外网出口 |

缺任何一条，就不该接这个 API。

# 四、系统里要有哪些控制（业务能检查的）

| 控制 | 作用 | 我们现在 |
| --- | --- | --- |
| 外网出口默认关闭 | 从根上不给出网 | **已满足**（代码零外网调用） |
| 本地 OCR 离线模型 | 解析不出机器 | **已满足**（RapidOCR 本地） |
| 口令不落库、不进日志 | 防密码泄露 | **已满足**（前端只内存使用） |
| 原件不进版本库 | 防误提交 | **已满足**（.gitignore 已覆盖 zip/pdf/图片） |
| 统一脱敏层 | 账号/姓名/证件/手机/对手方 | **缺**（只有零散提示，无统一函数） |
| 日志脱敏 | 日志里出现卡号即事故 | **缺**（无日志规范） |
| 外发白名单 | 只允许 L4 字段出网 | **缺**（无此机制） |
| 留存期限与删除 | 三年归档、到期清理 | **缺**（数据层未实现） |
| 访问控制与审计 | 谁能看哪份材料 | **缺**（后端未实现） |
| 入库存摘要不存原文 | 原件放对象存储，库里只放路径与哈希 | **契约已定，未实现** |

# 五、分阶段落地

| 阶段 | 目标 | 必须做到 |
| --- | --- | --- |
| 第一版（演示/试点） | 全本地，零外网 | 关外网、离线 OCR、口令不落库、原件不入库、脱敏函数 |
| 第二版（行内） | 接行内 OCR/解析服务 | 服务鉴权、网络隔离、审计、不留存 |
| 第三版（如需外部） | 只放派生数据 | 九条硬约束 + 可一键关闭 + 每次外发留痕 |

# 六、需要你拍板的五件事

| # | 事项 | 影响 |
| --- | --- | --- |
| 1 | 第一版是否「全本地、禁外网」 | 决定 OCR 方案与部署形态 |
| 2 | 行内 OCR 服务是否存在、能否提供 | 决定第二版能不能按期 |
| 3 | 若必须外部 API，允许传哪一层数据（只 L4？） | 决定是否要脱敏网关 |
| 4 | 留存期限（原件、明细、报告、审计） | 决定归档与删除策略 |
| 5 | 谁有权看原件（审批人？复核人？模板管理员？） | 决定权限模型与审计粒度 |

# 七、验收标准（可检查，不靠感觉）

| # | 检查项 | 通过条件 |
| --- | --- | --- |
| 1 | 断网运行 | 拔掉外网后，上传→解析→报告全流程可用 |
| 2 | 抓包 | 全程无任何外部域名请求 |
| 3 | 日志抽查 | 日志中搜不到账号、姓名、卡号原文 |
| 4 | 库表抽查 | 数据库中无原件二进制；账号字段为掩码 |
| 5 | 外发开关 | 关闭配置后，任何外发调用直接失败 |
