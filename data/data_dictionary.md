基线：当前 contract.md，变更日志日期 2026-10-26。

## 依据与边界

**契约确定内容**：十一表及关键字段逐字来自 contract.md「数据契约（十一张表）」。通用约定：金额 decimal(18,2)，接口字符串，禁止 JSON 浮点；时间存储与返回为 UTC+8、带偏移。载体由服务端判定，文件、任务、报告载体一致；报告仅银行可见。电子件、影像件、截图件遵守各自结论上限；影像件注明受限并人工复核，截图件不得作为授信依据。

**其他文档约定——数据库与留存**：data/Agent.md 规定 MySQL 8.4、utf8mb4、datetime；指标、报告、模板、规则、审计只增不改，审计禁 UPDATE/DELETE。data/design.md 要求跨库不建外键；业务库包括人员/文件/任务/账户/明细/模板/规则，指标报告单独库，审计单独库，appeal 归属待确认 Q01。design 要求图片原件不压缩，原件/明细/报告三年后归档，OCR 与明细同留存期，审计永久保留；删除边界见 Q04。

**数据库存储规则**：契约要求账号脱敏后落库；data/Agent.md 要求卡号前四后四、姓名留首字、身份证仅哈希、手机号中间掩码，OCR 中间结果同样处理。此处仅引用现有规则，不授权新增字段；姓名规则对工作人员等主体的适用范围待确认 Q04。

**角色展示规则**：data/design.md 规定默认不可见、按角色授权；账号不提供原文入口，姓名显示留首字但审批人在授权范围内可见原文，交易对手方按角色脱敏。展示权限不代表允许在数据库保存明文。

**待裁决实现边界**：授权原文如何与不落明文兼容、原件和 OCR 的保护方式均待 Q04 裁决；本草案不指定加密、视图、字段扩展或跨任务复用方案。

**待 PM/PD 确认内容**：Q01—Q09 与 chat.md 同编号。公共待确认项 Q05 适用于下列全部字段：未明确 SQL 类型、长度/精度、默认值、NULL、主键、索引、枚举实现及关系约束待确认，已有明确金额精度及业务枚举除外。字段行只列特有业务问题；“无新增特有问题”仍受公共待确认项约束。接口 string/int/array 不等于 SQL VARCHAR/INT/JSON。id 名称不自动确立主键。以下中文名、用途、粒度、关系及释义为语义草案，不新增物理约束，需业务审核。未明确值域均待确认，不将空值、空字符串或零混为一谈。

## 字段公共待确认项

Q05 统一适用于每个字段的未明确物理定义，包括 SQL 类型、长度/精度、NULL、默认值、主键及生成方式、索引、同库外键、关联基数与枚举实现。字段行无需重复引用；已有契约金额精度、唯一性、枚举和只增不改约束仍然有效。未明确业务值域仍待确认。下表中的“无新增特有问题”不代表物理定义已获批准。

文件唯一性不等同于任务复用权限：契约规定 file_obj.sha256 唯一，并以文件哈希支持创建任务判重；跨用户、跨任务类型或期间的文件/任务复用范围未定义，见 sha256 字段问题，不在此作决定。
