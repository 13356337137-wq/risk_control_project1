## 算法骨架

```
种子：表头里认出 >=2 个字段（各银行叫法不同也能认）
  ↓
扩散：顺着 y 往下找「形态对得上」的值（日期形/金额形/方向字/流水号形）
      用命中词的包络把带宽长出来，所以右对齐的金额列也能跟上
  ↓
收敛：一列至少命中 3 行才算成立；同一字段长出多条时保留命中最多的
  ↓
三档回落：锚点扩散(0.98) → 几何聚类(0.55~0.85) → 只用表头位置(0.45~0.65)
```

### 3. 只用 OCR 词也能重建版式（这是「质量差」的真实代理）

把 clean/icbc 渲染成 150dpi 图片（文本层彻底消失），只喂 OCR 词：

```
OCR 取词 7.0s，词数=27
方法=anchor_spread 置信=0.98
  txn_date  summary  counterparty  direction  amount  balance   ← 6 列全对
```

同一个图片件跑完整链路：旧路 3 笔、新路 3 笔（`layout.ocr=true`），图片件不再是一读就空。

## 一条必须说清的发现

问题：原以为「死模板」的病根是「没有表头就找不到列」，实测不是——封存版的 L2 通用解析 `parse_generic` 本来就是按形态推列的，我把表头整行抹掉，旧路照样读出 6 笔。解决状态：已确认，记在这里，M2 的差异化判据因此要改。事后反馈：如果继续用「有没有表头」当验收，新框架永远是「和旧版一样」，看不出价值；真正的差距在「词本身不准」（拍照歪斜、低分辨率、混版式、OCR 错字），这类样本目前一份都没有。下一步必须先把劣质样本集造出来，否则 M2 剩下的工作无法验收。

## 已知限制

- 多页版式目前按页独立检测（每页各自成一个区域），**没有**利用「首页/中间页/末页」的槽位先验；
  这对同版式流水够用，对「首页有表头、续页没有」的件依赖每页自己长出表头。
- 几何聚类只按横向间隙切列，遇到「摘要列里带空格、金额列紧贴」时会切多或切少。
- `layout.ocr` 默认关闭：OCR 单页约 7 秒，默认开会让电子件也被拖慢；
  只对「文本层为空」的件才触发。
- 版式坐标全部按页归一化到 0-1，中间没有做倾斜校正，所以斜 5° 以上的件列带会变宽、行会漏。
