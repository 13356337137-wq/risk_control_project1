# 报告证据与加密件口令

> 2026-11-14 · 分支 `rebuild/v1`

## 一、报告证据全是 [object Object]

## 问题

证据条目在接口里是对象 `{rule_code, page_no, txn_id, x, y}`——一次命中的「位置坐标」，
不是一句话。上一版用 `String(item)` 直接渲染，浏览器把它转成 `[object Object]`。

## 修法

改成表格：规则 / 页 / 笔号 / 页面坐标，并加「看这笔」跳转到交易流水。

顺带发现一个语义坑：证据里的 `txn_id` 不是数据库主键，而是**文件内的第几笔**（后端生成时用
`range(1, len+1)`）。所以「看这笔」按行号定位、自动翻到对应页并把该行滚到视野中间，
而不是按 id 匹配（按 id 匹配永远匹配不到，实测列表 id 是 14124 起，证据写的是 28）。

## 二、加密 PDF 报「No password given」

## 问题

加密件在三条路上都会撞到这句话，而且它是 pymupdf / pdf.js 的英文原文，用户看不懂：

| 路径 | 现象 |
| --- | --- |
| 借款人上传 | 已支持口令，但错口令也会受理成一个注定失败的任务 |
| 标注画布打开原件 | `版式分析失败：No password given`，没有输口令的地方 |
| 标注画布渲染 PDF | `PDF 渲染失败：No password given` |

## 修法

1. 版面分析入口（`layout/words.read_pages`）接受口令，并把两种情形分开报：
   没给口令 → 「PDF 设有打开口令，请输入口令后再分析」；给了但打不开 → 「口令不正确，请重新输入」。
2. Lab 新增的 `POST /lab/inspect-file`、`/lab/spread-file` 接受 `password` 表单字段，
   口令问题返回 `E_ENCRYPT`（前端据此弹口令框，而不是报「分析失败」）。
3. 标注画布：出现 `E_ENCRYPT` 或 pdf.js 的口令异常时，顶部弹出「这份 PDF 的打开口令」输入框，
   回车或点按钮即用该口令重新分析并重渲染。
4. 后端上传：口令**当场校验**（`services.analysis.password_opens`），错口令直接 400 拒绝，
   不再生成一个注定失败的任务；失败也计入尝试次数。

## 实测

```
POST /lab/inspect-file 无口令        → 400 E_ENCRYPT「PDF 设有打开口令，请输入口令后再分析」
POST /lab/inspect-file password=9999 → 400 E_ENCRYPT「口令不正确，请重新输入」
POST /lab/inspect-file password=1234 → 200，1 页 6 条列带
POST /tasks 无口令                  → 400 E_ENCRYPT「PDF 需要打开口令」
POST /tasks password=9999           → 400 E_ENCRYPT「口令不正确，请重新输入」
POST /tasks password=1234           → 202 受理（任务 #154）
```

报告证据（任务 #150）：39 条，表格显示 `INCOME_UNSTABLE / FAST_IN_OUT + 页 + 笔号 + 坐标`；
点「看这笔」跳到交易流水、翻到对应页、目标行带琥珀色标记并滚到中间。

## 没验证的

标注画布的口令输入框没有在浏览器里走通——无头浏览器点不开系统文件框，
所以「选加密文件 → 弹口令框 → 输入 → 渲染」这条链只有 API 侧证据，UI 侧等人工点一次。
